# 📝 对话总结:今天做了什么、解决了什么

> 这是 2026-08-12 到 08-13 与 AI 助手协作的记录总结。按时间线讲三个大件事:修 mkEditor 的 CI → 清理仓库历史 → 从零建官网。

## 一、mkEditor 打包反复失败,最终修好

**背景**:mkEditor 的 GitHub Actions(`build.yml`)要一键打包三平台(Windows/macOS/Linux)安装包并发布。

**过程**:连续失败 4 次,一次一个坑:

1. **路径通配符写错** — 打包目标路径匹配不到文件
2. **`--config package.json` 写法有问题** — 配置没读对
3. **lockfile 报错** — 见下方"历史清理"
4. **`--publish` 参数问题** — 一度担心误发 Release

**解决**:逐一排查修复,最终 CI 全绿,能正常打 tag 出三平台安装包。完整约定见 [[06-mkEditor-发布流程]]。

**教训**:CI 是"照配置执行的机器",错一点就全挂;但每修一个错,配置就清晰一分。

## 二、package-lock.json 的历史清理(重要!已解决)

**问题**:mkEditor 早期把 `package-lock.json` 提交进了 git 历史。但项目**刻意不用 lockfile**(CI 用 `npm install` 而非 `npm ci`),旧 lockfile 在 CI 里引发报错。

**解决**:把 lockfile **从整个 git 历史中抹除**:

- `git reset --soft` 回退 + 删除 lockfile + `commit --amend`
- 处理了历史里的 tag,重新打 tag 推送
- **后果提醒**:远程被覆盖过,如果多人协作要格外小心

**约定(写进记忆,永久生效)**:
- mkEditor 仓库:**lockfile 不入库**,CI 用 `npm install`
- 官网仓库:**lockfile 入库**,CI 用 `npm ci`(正好相反,因为官网依赖要精确复现)

## 三、官网从 0 到 1(今天的重头戏)

1. **头脑风暴**:你说想给 MarkdownSoft 做个官网展示,用 github.io
2. **设计方案**:定下 Vue 3 + Vite + TS、中英双语、四主题、GitHub Pages 部署
3. **写计划**:拆成 7 个任务(骨架 → 语言 → 主题 → 布局 → 特性卡片 → 下载区 → 图标/部署)
4. **分工实现**:每个任务派一个子 AI 实现,完成后由另一个 AI 审查;审查发现问题 → 修复 → 再审查
5. **全分支终审**:最强大模型通读全部分支代码,裁决"可以合并",顺手压缩了 2.4MB 的大图标到 77KB
6. **合并上线**:合并进 main,推送到 GitHub,触发自动部署
7. **白屏事故**:见下一条

**过程中的两个小插曲**:
- 任务简报文件一度出现中文乱码(编码问题),重新生成解决
- 子 AI 一度漏了计划里"导入主题 CSS"这一步,恢复实现者补做

## 四、白屏事故(上线后才发现)

**现象**:部署全绿,页面空白。详见 [[03-GitHub-Pages]] 的完整分析。

**一句话根因**:Pages 默认用"从分支直接发布"模式,发的是源码(TypeScript 浏览器跑不了);得改成"GitHub Actions"模式,发布构建产物。

**修复**:Settings → Pages → Source 选 **GitHub Actions** → Re-run workflow。这一步需要你在网页上手动完成(我没法替你点)。

## 五、几个值得记住的技术决策

| 决策 | 为什么 |
|------|--------|
| vitest 用 **3.2.4**(不是计划的 2.x) | 2.x 与 Vite 6 不兼容,编译不过 |
| 下载链接独立成 `constants.ts` | Vue `<script setup>` 里不能直接 export 常量,独立文件才能到处引用 |
| 部署用 Node **22** | 与本地环境一致,减少环境差异 |
| 语言/主题偏好存 **localStorage** | 用户下次打开记住选择 |
